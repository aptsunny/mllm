**原因分析**:
- 配置文件中 `tie_word_embeddings` 设置为 `true`
- 代码尝试加载 `lm_head_out.weight` 参数
- 但模型文件中只有 `lm_head.weight` 参数
- 导致参数加载失败，程序崩溃

## 问题分析

### 问题 1: Tokenizer 词汇表不匹配

**现象**:
- 模型配置 vocab_size: 151,936
- Tokenizer 实际大小: 151,669
- 差异: 268 个 token

**影响**:
- 模型输出的 token ID 可能超出 tokenizer 的范围
- 导致解码失败，输出异常字符（如 "N" 或 "!"）

**原因**:
- 模型文件和 tokenizer 来自不同版本
- 量化过程中词汇表大小不一致

**解决方案**:
1. 获取与模型匹配的 tokenizer
2. 修改配置文件中的 vocab_size（但会导致 embedding 层形状不匹配）
3. 重新转换模型确保一致性

### 问题 2: 模型参数名称不匹配

**现象**:
- 配置文件中 `tie_word_embeddings` 设置为 `true`
- 代码尝试加载 `lm_head_out.weight`
- 模型文件中只有 `lm_head.weight`

**影响**:
- 参数加载失败
- 程序崩溃

**原因**:
- 模型文件使用 `lm_head.weight` 作为参数名
- 代码在 `tie_word_embeddings` 为 true 时期望 `lm_head_out.weight`

**解决方案**:
1. 设置 `tie_word_embeddings` 为 `false`（当前方案）
2. 修改代码支持 `lm_head.weight` 参数名
3. 重新转换模型使用 `lm_head_out.weight` 参数名

### 问题 3: 输出质量异常

**现象**:
- 英文输入输出大量 "N" 字符
- 中文输入输出大量 "!" 字符

**影响**:
- 无法正常使用模型进行推理
- 输出结果不可读

**原因**:
- Tokenizer 词汇表不匹配导致解码失败
- 模型输出的 token ID 超出 tokenizer 范围

**解决方案**:
- 需要获取与模型匹配的 tokenizer
- 或者修复 tokenizer 词汇表大小

## 结论

### 成功部分

1. ✅ **模型加载成功**: FP32 和 Q4_K 模型都能正常加载
2. ✅ **Tokenizer 初始化成功**: tokenizer.json 文件正确读取
3. ✅ **配置生效**: 配置文件参数正确应用
4. ✅ **推理完成**: 程序成功完成推理循环
5. ✅ **性能指标正常**: Prefill 速度达到预期

### 失败部分

1. ❌ **输出质量异常**: Tokenizer 解码失败，输出不可读
2. ❌ **词汇表不匹配**: 模型配置和 tokenizer 不一致
3. ❌ **参数名称不匹配**: `tie_word_embeddings` 配置导致崩溃

### 根本原因

**核心问题**: 模型文件和 tokenizer 不匹配

- 模型文件按照 151,936 个 token 训练
- Tokenizer 只有 151,669 个 token
- 差异 268 个 token 导致解码失败

### 建议解决方案

1. **获取正确的 tokenizer**（推荐）
   - 从官方 ModelScope 下载完整的 tokenizer
   - 确保 tokenizer 与模型版本匹配

2. **重新转换模型**
   - 使用正确的 tokenizer 重新转换模型
   - 确保词汇表大小一致

3. **修改配置文件**
   - 调整 vocab_size 以匹配 tokenizer（但会导致 embedding 层形状不匹配）
   - 不推荐此方案

4. **修复代码支持**
   - 修改 Qwen3 模型代码以支持不同的参数名称
   - 添加更灵活的配置选项
